# Background credential safety

- Startup discovery and periodic health checks use only the current process's cached provider-key state. They never read or write provider Keychain items. A key is `unknown` until successfully read or written in this process; a successful item-not-found result is `missing`; a successful read/write is `found`. Read failures remain unknown, not missing.
- Unknown providers are skipped by background reachability and model probes, preserving their health and eviction state. Known-missing providers can be probed without a key (for unauthenticated local services); known-found providers use their cached key. A genuine upstream failure can still affect health and eviction as before.
- Automatic discovery may still read local application configuration files and scan configured local ports, but does not import discovered credentials into Keychain. Newly discovered providers therefore remain unverified until an explicit operation authorizes or imports a key. Use the explicit discovery button or connection test when authorization is appropriate.
- An explicit discovery, connection test, or model probe may read Keychain and show a macOS authorization prompt. An explicit discovery can import credentials; if reading or writing a key fails, that provider is skipped for that probe rather than tested anonymously. A blank provider-editor key field preserves the existing item; use the clear toggle to delete it.
- Cache state is process-local, not a live monitor of external Keychain changes or revocation. Restarting makes provider states unknown again; external changes may not be reflected until restart or an in-app update. Reads of a previously found item use the cached value. The existing boolean `hasAPIKey` is cache-only and cannot distinguish unknown from missing; UI that presents status must use `cachedAPIKey`.
- The focused regression tests use fake Keychain and URLProtocol transports and temporary fixture homes, under a sandbox denying network, securityd, and real-home access. They do not validate real macOS Keychain ACL prompts, external key changes, or interactive SwiftUI rendering. The full suite was not run because other tests may use real local services or home paths.
